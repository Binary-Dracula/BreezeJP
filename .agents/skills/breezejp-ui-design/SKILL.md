# BreezeJP UI 设计规范

本 Skill 是 BreezeJP 项目的项目级 UI 规范。后续 Agent 在实现 Flutter 页面、组件、样式调整、页面重构时，应优先遵守本文件，而不是直接套用通用 UI 模板。

目标只有一个：**延续当前产品已经形成的视觉语言，并将其整理成统一、可执行的设计系统。**

## 1. 使用范围与强制原则

- 适用于所有 Flutter 页面、组件、弹窗、空态、错误态、列表卡片、详情页、设置页、学习页、阅读页。
- 优先复用当前项目已经存在的颜色关系、圆角尺度、卡片风格、间距节奏，不凭空引入新的品牌主色。
- 设计决策以现有页面为准，优先参考以下母版：
  - `lib/features/home/pages/home_page.dart`
  - `lib/features/vocabulary_book/pages/vocabulary_book_page.dart`
  - `lib/features/article/pages/article_list_page.dart`
  - `lib/features/learn/pages/learn_page.dart`
- 如果通用 Skill（如 `ui-ux-pro-max`）与本文件冲突，以本文件为准。
- 所有用户可见文案仍必须走 `AppLocalizations`，UI 规范不能绕过工程规范。

## 2. 项目视觉基线

### 2.1 全局主题基线

- 当前应用的全局主题入口位于 `lib/main.dart`。
- 使用 `ThemeData` + `ColorScheme.fromSeed(seedColor: Color(0xFF1E88E5))`。
- 已启用 `useMaterial3: true`，但项目视觉并不是默认 Material 3 原生样式，而是基于 Material 能力做了项目化定制。

### 2.2 当前产品气质

- 这是一个日语学习应用，不是工具后台，也不是极简资讯 App。
- 整体风格应保持：轻量、清爽、学习导向、卡片化、带少量渐变强调。
- 页面普遍使用浅色背景、白色或浅色卡片、高可读正文、局部彩色强调，而不是大面积重色块。
- 重要入口允许使用更饱和的渐变卡片，但普通信息卡片应保持克制。

## 3. 颜色系统

### 3.1 品牌与语义主色

以下颜色来自当前页面实现，后续新增页面应优先复用这些语义色：

| 语义     | 颜色                  | 用途                                    |
| -------- | --------------------- | --------------------------------------- |
| 品牌蓝   | `#1E88E5`             | 全局 seed color，应用主品牌基线         |
| 学习主蓝 | `#5C8DFF`             | 词汇学习、Tab 激活、主要 CTA            |
| 阅读靛蓝 | `#6366F1`             | 阅读模块、文章入口、JLPT 标签、图表强调 |
| 复习青绿 | `#14B8A6`             | 统计对比、词性标签、辅助强调            |
| 天空蓝   | `#0EA5E9`             | 假名相关渐变、统计辅助色                |
| 成功绿   | `#34D399` / `#22C55E` | 假名、掌握态、正向反馈                  |
| 紫色强调 | `#8B5CF6` / `#7C3AED` | 语法入口、次品牌级强强调                |
| 警示橙   | `#F59E0B` / `#FBBF24` | 工具入口、需要提醒的亮色强调            |
| 错误红   | `#FF6B6B` / `#EF4444` | 错误、答错、失败反馈                    |

### 3.2 背景层级

当前项目存在多个浅背景，不应视为混乱，而应整理为有场景差异的背景层级：

| 场景         | 颜色      | 规则                                                           |
| ------------ | --------- | -------------------------------------------------------------- |
| 默认页面背景 | `#F6F7FB` | 大多数业务页面默认使用，如首页、词书、设置、统计、登录相关页面 |
| 内容列表背景 | `#F8FAFC` | 内容感更强的列表页可用，如文章列表                             |
| 阅读沉浸背景 | `#FDFBF7` | 阅读正文、文本沉浸型页面、控制栏底色                           |
| 输入浅底     | `#F1F3F5` | 搜索栏、浅输入框、低对比控件底色                               |
| 白色卡片底   | `#FFFFFF` | 标准卡片、AppBar、浮层、主要内容容器                           |

裁决规则：

- 普通业务页优先 `#F6F7FB`。
- 只有在“信息阅读感”明显强于“操作感”时，才用 `#F8FAFC`。
- 只有在文章阅读、文本控制、沉浸式正文场景时，才用 `#FDFBF7`。
- 不要为新页面再发明第四种大面积背景色。

### 3.3 推荐渐变

项目已经形成了几组明确的功能型渐变，新增页面应优先从这里选：

| 功能         | 渐变                                       |
| ------------ | ------------------------------------------ |
| 假名入口     | `#34D399 -> #0EA5E9`                       |
| 单词学习入口 | `#5C8DFF -> #6DD5ED`                       |
| 语法入口     | `#8B5CF6 -> #7C3AED`                       |
| 阅读入口     | `#6366F1 -> #4F46E5`                       |
| 工具类强调   | `#14B8A6 -> #0D9488`、`#FBBF24 -> #F59E0B` |

规则：

- 渐变主要用于首页一级入口卡片、模块主按钮、带品牌感的功能入口。
- 普通列表卡片、表单页、设置页不要滥用渐变背景。
- 如果新页面没有明显的“一级功能入口”，优先使用纯色卡片而不是硬加渐变。

## 4. 文本与排版规则

### 4.1 字体现实约束

- 当前项目未在 `pubspec.yaml` 中配置自定义字体，也未引入 `google_fonts`。
- 因此后续页面默认应继续使用 Flutter / 系统字体栈，不擅自引入新的品牌字体。
- 日语内容以可读性优先，避免过分装饰化、过细、过窄的字体决策。

### 4.2 文本层级

结合现有页面，推荐按以下层级组织：

| 层级        | 推荐尺寸 | 字重                       | 用途                         |
| ----------- | -------- | -------------------------- | ---------------------------- |
| 页面主标题  | 24       | `FontWeight.bold`          | 首页欢迎、重要页面抬头       |
| AppBar 标题 | 18       | `FontWeight.bold`          | 词书、列表页、标准子页面     |
| 分区标题    | 16       | `FontWeight.w700`          | 首页 section title、区块标题 |
| 卡片标题    | 16-17    | `FontWeight.bold` / `w600` | 列表卡片标题、功能卡标题     |
| 正文主体    | 14-16    | `normal` / `w500`          | 列表说明、描述、正文块       |
| 辅助说明    | 12-14    | `normal`                   | 副标题、弱说明、空态说明     |
| 标签文字    | 11-12    | `FontWeight.w600`          | JLPT、词性、小状态标签       |

### 4.3 文本颜色裁决

- 内容型页面标题优先使用 `#1E293B`。
- 通用业务页标题可以继续使用 `Colors.black87`，但同一页面内部不要混用多个主标题色。
- 辅助文本优先使用 `#64748B` 或灰色系，不使用过亮颜色承载大段说明文字。
- 复习/测验旧页面中出现的 `#2D3142`、`#6C63FF` 视为该模块保留色，新增通用页面不要主动扩散这组旧配色。

## 5. 间距、圆角、阴影

### 5.1 间距尺度

当前页面的主流节奏已经比较稳定，后续统一按下面的尺度使用：

| 语义  | 数值 | 说明                                 |
| ----- | ---- | ------------------------------------ |
| `xs`  | 4    | 紧贴元素的微间距                     |
| `sm`  | 8    | 紧凑型控件、图标与文字               |
| `md`  | 12   | 小卡片间距、区块内间距               |
| `lg`  | 16   | 常规页面内边距、卡片内容边距         |
| `xl`  | 20   | 首页主内容横向 padding、主卡片内边距 |
| `xxl` | 24   | 大区块分隔、页面段落节奏             |

补充规则：

- `6` 可以继续用于非常紧的小尺寸间距，但不要把它当作页面主节奏。
- 页面横向主 padding 优先 `16` 或 `20`，不要频繁混用奇怪值。

### 5.2 圆角尺度

| 场景                 | 推荐圆角 |
| -------------------- | -------- |
| 小标签、小输入控件   | 8        |
| 搜索框、普通按钮     | 12       |
| 标准卡片、列表卡片   | 16       |
| 主入口卡片、强调容器 | 18-20    |

规则：

- 一页内尽量只出现 2 到 3 个层级的圆角。
- 不要在同一页面同时出现 10、14、18、22 这种无规律圆角。

### 5.3 阴影尺度

| 层级   | 建议写法                             | 用途                           |
| ------ | ------------------------------------ | ------------------------------ |
| 低阴影 | `blur 10 / offset(0,4) / alpha 0.04` | 列表卡片、信息卡               |
| 中阴影 | `blur 12 / offset(0,6) / alpha 0.03` | 统计卡、悬浮区块               |
| 高阴影 | `blur 16 / offset(0,10)`             | 仅用于首页主入口或高强调渐变卡 |

规则：

- 阴影是层次补充，不是视觉主角。
- 不要为普通白卡片叠过强阴影。
- 深色阴影透明度保持很低，优先营造轻量感。

## 6. 常用组件规范

### 6.1 AppBar

- 标准子页面优先白底 AppBar。
- 标题居中，字重为 `bold`。
- 返回按钮优先使用当前项目已有的 iOS 风格小尺寸返回图标。
- `elevation` 保持低或为 `0`，只在需要滚动分层时使用轻微 `scrolledUnderElevation`。

### 6.2 搜索栏与 Tab 结构

参考 `vocabulary_book_page.dart`：

- 搜索栏容器为白底区块。
- 输入框底色优先 `#F1F3F5`。
- 输入框圆角优先 `12`。
- 激活 Tab 的强调色优先 `#5C8DFF`。
- Tab 指示器保持清晰，但不要做复杂装饰。

### 6.3 标准信息卡片

参考文章列表、统计卡、普通列表项：

- 卡片底色优先白色。
- 圆角优先 `16`。
- 内容 padding 优先 `16` 或 `20`。
- 默认配低阴影。
- 卡片内若包含图标块，可使用项目既有渐变作为图标背景，但正文区域仍应保持干净。

### 6.4 首页一级入口卡片

参考 `home_page.dart`：

- 允许使用高饱和渐变。
- 应有明确的信息层级：标题、简短说明、图标、动作提示。
- 视觉上要显著高于普通卡片，但数量不宜过多。
- 新增首页入口时，应先复用现有渐变语义，再考虑新增组合。

### 6.5 标签与状态胶囊

- JLPT 标签优先使用靛蓝系 `#6366F1`。
- 词性或辅助分类标签优先使用青绿系 `#14B8A6`。
- 成功、掌握、可继续操作的状态优先绿色系。
- 标签应保持紧凑：小字号、轻背景、较小圆角，不做重按钮化设计。

### 6.6 按钮

- 主按钮优先纯色或项目语义渐变，不要无理由使用随机新色。
- 列表页、登录引导、主要 CTA 可使用 `#5C8DFF` 或 `#6366F1` 作为主按钮底色。
- 次按钮优先描边或浅底，而不是再造一个第二主色。
- 同一页面最多保留一个“最强 CTA”视觉样式。

### 6.7 学习页与底部操作区

参考 `learn_page.dart`：

- 学习详情页使用“顶部轻操作栏 + 中部纵向内容 + 底部固定 action bar”的结构。
- 内容区域应优先保证词条、释义、例句的阅读连续性，不被过多装饰打断。
- 底部操作区要承担高频学习动作，视觉应清晰、固定、易点击。
- 学习页更偏沉浸式，不适合堆叠大量彩色卡片。

## 7. 页面模板

### 7.1 首页仪表盘型页面

参考：`lib/features/home/pages/home_page.dart`

结构建议：

- 浅背景 + `SafeArea`
- 顶部欢迎区
- 多个分区标题
- 一级功能卡
- 复习区块
- 统计区块
- 工具区块

适用场景：主页、总览页、学习入口聚合页。

### 7.2 书籍 / 目录 / Tab 检索型页面

参考：`lib/features/vocabulary_book/pages/vocabulary_book_page.dart`

结构建议：

- 白底 AppBar
- 可切换搜索栏
- 顶部 TabBar
- 下方列表区
- 标签与状态信息在列表项内展示

适用场景：词书、语法书、收藏列表、历史列表。

### 7.3 内容卡片列表型页面

参考：`lib/features/article/pages/article_list_page.dart`

结构建议：

- 轻背景
- 标准卡片列表
- 左侧或顶部图标/插图块
- 卡片标题 + 副标题 + 跳转反馈

适用场景：文章列表、资源列表、主题推荐列表。

### 7.4 沉浸式学习详情页

参考：`lib/features/learn/pages/learn_page.dart`

结构建议：

- 顶部轻量控制区
- 主内容纵向滚动
- 底部固定操作栏
- 弹窗与路径结束反馈保持简洁，优先任务导向

适用场景：学习详情、练习详情、逐步浏览内容页。

## 8. Agent 执行清单

Agent 在开始新的 Flutter UI 任务时，应按以下顺序执行：

1. 先判断新页面最接近哪一个现有母版页面。
2. 先选背景层级，再选主强调色，而不是先画组件。
3. 优先复用本文件的语义颜色、渐变、圆角、间距和卡片规则。
4. 检查页面是否包含用户可见文案；如果包含，必须接入 `AppLocalizations`。
5. 检查页面是否需要搜索、Tab、卡片、底部操作区，并复用本文件的模板规则。
6. 如果需要新增一个此前没有的视觉样式，先说明为什么现有母版不足，再做最小偏离。

## 9. 明确禁止项

- 禁止把新页面做成与当前项目完全不同的品牌风格。
- 禁止无理由引入新的主品牌色、深色主题风格、霓虹风、玻璃拟态、重金属渐变等强风格表达。
- 禁止在普通业务页面大面积堆叠多个高饱和渐变卡片。
- 禁止忽略当前项目已经形成的浅背景 + 白卡片 + 彩色强调结构。
- 禁止在一个页面中混入过多字号、圆角、阴影尺度。
- 禁止为了“好看”牺牲日语文本可读性。
- 禁止绕过 `AppLocalizations`、路由规范、Riverpod 架构边界。

## 10. 已知不一致与裁决规则

当前代码中已经存在少量历史差异，后续 Agent 应按以下方式裁决：

- 背景色存在 `#F6F7FB`、`#F8FAFC`、`#FDFBF7` 三类：按默认业务页、内容列表页、阅读沉浸页划分，不再随意新增。
- 主标题深色既出现 `Colors.black87`，也出现 `#1E293B`：新增内容页优先 `#1E293B`，通用业务页可保留 `black87`，但同页不混用。
- 复习模块存在旧紫色 `#6C63FF`：视为旧模块语义色，仅在该模块及紧邻组件中延续。
- 当前项目没有统一 design tokens 文件：在真正抽取主题代码之前，新增页面先遵循本 Skill 的命名化规则，不要继续扩散新的魔法数。
